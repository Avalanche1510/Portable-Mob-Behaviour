# 关于 热插拔怪物AI 的文档

## 简介

本模组引入了新的，高度自定义的，相对简单的怪物的AI行为数据结构。
该数据结构可以通过使用指令或数据包，在游戏内即时修改并生效，立刻修改或允许特定的AI行为。
可选的参数和定义数据结构的语法将在下方给出。

## 双端部署与同步

本模组构建为一个同时用于客户端和服务端的通用JAR，但公共与客户端源码已经通过Loom source set分离。专用服务端只加载公共和服务端逻辑，模型、渲染与客户端Mixin只在物理客户端加载。

客户端和服务端均必须安装本模组。连接配置阶段会交换独立的PMB网络协议号；客户端缺少本模组、服务器缺少本模组或协议不兼容时会在进入世界前断开连接并显示原因。模组显示版本不要求完全一致，只要求网络协议兼容。

AI决策、伤害和PmbAi配置始终由服务端负责。举盾、拉弓、手持物和旋转使用原版同步状态；破盾虚弱剩余时间使用SynchedEntityData同步，以便远程客户端正确显示抖动。完整PmbAi配置不会发送给客户端。

## 动态Faction派系

Faction是独立于PmbAi技能的服务端动态关系模块。玩家和所有LivingEntity均可加入一个派系，但不能同时属于两个派系。成员身份保存在实体根NBT中：

```text
PmbFaction:{
    FactionName:"EmpireGuard"
}
```

FactionName是区分大小写的普通字符串，不受Minecraft资源ID的`namespace:path`和小写限制。指令中直接输入不含空白的名称，不需要添加引号，例如`EmpireGuard`、`北方联盟`或`Raiders-02`。FactionName必须对应已经创建的服务端派系。删除派系会清除已加载成员；未加载成员在下次加载时清除失效名称。玩家死亡重生后保留成员身份。

PmbFaction不是客户端显示用的临时数据，而是由服务端读取和保存的实体持久NBT；完整成员关系不会同步给客户端。可以在生成实体时直接写入，无需先生成再使用选择器：

```mcfunction
/pmb faction create 灾厄庭
/summon minecraft:vindicator ~ ~ ~ {PmbFaction:{FactionName:"灾厄庭"}}
/summon minecraft:pillager ~ ~ ~ {PmbFaction:{FactionName:"灾厄庭"},PmbAi:{bow:{enable:1b}},equipment:{mainhand:{id:"minecraft:bow"}}}
/data merge entity @e[type=minecraft:vindicator,sort=nearest,limit=1] {PmbFaction:{FactionName:"灾厄庭"}}
```

`/summon`只写入成员身份，不会自动创建派系；对应派系必须已经存在于服务端SavedData中，且FactionName必须大小写完全一致。不存在的名称会在实体的下一个服务端tick被清除。数据包函数可以先创建派系，再在同一函数中直接执行带PmbFaction的summon。

派系定义保存在服务端主世界SavedData中并由所有维度共享，不会把完整规则同步给客户端：

```text
Factions:{
    "EmpireGuard":{
        Rules:{
            allowInternalConflict:0b,
            allowFriendlyFire:1b,
            groupRevenge:0b,
            overrideTeamRules:1b,
            defaultAttitude:"neutral",
            evasiveSpeedMultiplier:1.25f
        },
        VanillaCompatRules:{
            piglin:{
                greed:1b,
                guarding:1b,
                avoidance:1b
            }
        },
        Relationships:[
            {
                attitude:"hostile",
                target:{
                    factions:["Raiders"],
                    teams:["red"],
                    types:["minecraft:zombie","#minecraft:undead"],
                    tags:["traitor"],
                    reputation:["1..100"],
                    roles:["guard"]
                }
            }
        ],
        Players:{
            "<uuid>":{
                reputation:0,
                roles:["guard"]
            }
		}
	}
}
```

### Rules

- `allowInternalConflict`：默认`0b`。关闭时同派系成员固定按allied处理；开启后Relationships和defaultAttitude可以使同派系成员敌对或逃避。
- `allowFriendlyFire`：默认`1b`。设为`0b`时，由受击方派系阻止member或allied造成的近战、投射物和有责任者爆炸伤害。环境伤害不受影响。
- `groupRevenge`：默认`0b`。启用后，member或单向allied对象受击会使附近成员使用各自FOLLOW_RANGE反击责任者；不会反击另一个member或allied。
- `overrideTeamRules`：默认`1b`。启用时Faction可以覆盖原版team对同队索敌、反击和友伤的限制；关闭时同team关系优先遵守原版规则。
- `defaultAttitude`：默认`"neutral"`。控制没有匹配任何Relationship的目标。
- `evasiveSpeedMultiplier`：默认`1.25f`，值域`[0.0f,100.0f]`。控制两种逃跑行为使用的导航速度倍率。

### VanillaCompatRules

VanillaCompatRules与Rules、Relationships平级，专门控制Faction如何保留各类原版Brain生物的物种特色。内部先按生物分组，再填写该生物的兼容规则；缺少整个集合、缺少生物组或缺少单项时均使用默认值。当前支持：

- `piglin.greed`：默认`1b`。保留普通猪灵拾取、欣赏和交易黄金的行为；关闭时阻止新的黄金拾取或欣赏，并清理相关Brain记忆。
- `piglin.guarding`：默认`1b`。允许neutral普通猪灵保留打开受保护容器、破坏金块等原版事件产生的ANGRY_AT并发起攻击；关闭后neutral仍可在实际受击时反击。
- `piglin.avoidance`：默认`1b`。保留普通猪灵对僵尸猪灵等僵尸化生物及其他原版AVOID_TARGET的规避；该兼容规则高于Faction hostile，因此启用时不会把原版要求规避的目标设为Faction战斗目标。设为`0b`后压制原版规避，此时派系hostile可以使猪灵主动攻击僵尸猪灵。passively_evasive和actively_evasive产生的PMB规避不受此项影响。

猪灵蛮兵对PMB目标的合法性兼容属于防止Brain状态循环的必要修复，不是可关闭的特色行为，因此不放入piglin组。后续生物会以`hoglin:{...}`、`warden:{...}`等独立组加入，不会把不同生物的字段混在同一级。

灾厄村民的Faction战斗兼容同样不改变非战斗状态的原版特色行为。掠夺者和卫道士获得有效Faction战斗目标时，会暂时退出巡逻队原版“原地警戒并等待目标靠近”的HoldGround行为；正在寻路返回袭击或回收袭击旗帜的Raider也会先进入Faction战斗。目标失效后，这些原版行为仍可按原条件重新启动。唤魔者原版没有主动接近敌人的战斗Goal，因此会在非施法阶段接近Faction目标至16格以内，再继续使用原版唤魔与尖牙施法；该行为不提供新的伤害方式。

### Relationships和态度

Relationships按列表顺序检查，最后一条匹配规则生效。单个target中所有非空类别之间为AND；同一数组内的多个值为OR。空target不允许写入。

- `factions`匹配目标唯一的FactionName；`teams`匹配原版记分板team名称。
- `types`接受实体类型ID或以`#`开头的实体类型标签；`tags`匹配实体的`/tag`。
- `reputation`接受精确值`"5"`、上界`"..100"`、下界`"1.."`和闭区间`"1..100"`。
- `reputation`与`roles`只匹配玩家，并读取目标玩家在规则所属派系中的Players记录；玩家不需要加入该派系即可拥有记录。

五种态度的固定语义：

- `hostile`：在自身FOLLOW_RANGE内发现可见目标后主动索敌；暂时失去视线仍可继续追击，离开范围后清除目标。
- `neutral`：不主动索敌，受到有效攻击后允许反击。`VanillaCompatRules.piglin.guarding:1b`时，猪灵打开受保护容器、破坏金块等原版事件产生的ANGRY_AT属于保留的物种特有被动敌意，也可以触发攻击。
- `allied`：不主动索敌且不反击；是否阻止实际伤害由受击方allowFriendlyFire决定。
- `passively_evasive`：受到攻击后开始逃跑，直到攻击者离开自身FOLLOW_RANGE。
- `actively_evasive`：可见目标进入自身FOLLOW_RANGE时主动逃跑，目标离开范围后停止。

Faction的扫描、反击、已有目标验证和猪灵专用Brain目标解析均会排除死亡实体，以及处于创造或旁观模式的玩家。即使此类玩家攻击成员，也不会被写入Faction战斗或规避目标。猪灵、猪灵蛮兵与疣猪兽的原版受击反击入口同样会在非生存模式攻击者处停止，避免原版Brain与Faction目标反复争夺而出现举起武器、放下武器和怒吼循环。

Faction态度覆盖成员的原版主动敌意，同时管理普通Mob目标和Brain的ATTACK_TARGET/AVOID_TARGET。对Goal生物，PMB会在原版targetSelector完成后、攻击与移动goalSelector运行前重新确认Faction目标，避免原版较短的索敌距离清除FOLLOW_RANGE内的远距离目标；PMB不会因此新增通用近战Goal。仅在Brain注册了对应MemoryModule时才读取记忆，并且仅在目标变化时写入；Faction不会无条件清除未由PMB持有的原版AVOID_TARGET。猪灵和猪灵蛮兵使用专用兼容层，使PMB战斗目标通过原版目标合法性检查，同时保留neutral猪灵由原版ANGRY_AT驱动的守卫与贪婪行为。灾厄巡逻队的HoldGround、袭击寻路和旗帜回收不会压住更高优先级的Faction战斗；没有原版接近Goal的唤魔者只获得进入原版施法有效距离所需的专用导航，不获得新攻击。hostile只提供目标，不会为没有攻击行为的生物凭空添加近战技能。两种evasive复用已经指向远离威胁方向的有效导航路径；需要重新寻路时优先选择生物寻路系统确认可达的远离位置。地面寻路失败时不会把移动控制器直接指向墙内或其他不可达坐标，飞行与水生导航仍可使用稳定的直接远离移动。

### `/pmb faction`指令

所有管理指令要求游戏管理员权限。主要语法如下：

```mcfunction
/pmb faction create <faction>
/pmb faction delete <faction>
/pmb faction list
/pmb faction info <faction>
/pmb faction rule set allowInternalConflict <faction> <true|false|1b|0b>
/pmb faction rule set allowFriendlyFire <faction> <true|false|1b|0b>
/pmb faction rule set groupRevenge <faction> <true|false|1b|0b>
/pmb faction rule set overrideTeamRules <faction> <true|false|1b|0b>
/pmb faction rule set defaultAttitude <faction> <attitude>
/pmb faction rule set evasiveSpeedMultiplier <faction> <float>
/pmb faction compat set piglin greed <faction> <true|false|1b|0b>
/pmb faction compat set piglin guarding <faction> <true|false|1b|0b>
/pmb faction compat set piglin avoidance <faction> <true|false|1b|0b>
/pmb faction relationship add <faction> <attitude> <target_snbt>
/pmb faction relationship insert <faction> <index> <attitude> <target_snbt>
/pmb faction relationship replace <faction> <index> <attitude> <target_snbt>
/pmb faction relationship remove <faction> <index>
/pmb faction relationship move <faction> <from> <to>
/pmb faction relationship list <faction>
/pmb faction member set <faction> <entities>
/pmb faction member clear <entities>
/pmb faction member get <entity>
/pmb faction reputation set <faction> <players> <value>
/pmb faction reputation add <faction> <players> <value>
/pmb faction reputation get <faction> <players>
/pmb faction role add <faction> <players> <role>
/pmb faction role remove <faction> <players> <role>
/pmb faction role clear <faction> <players>
/pmb faction role list <faction> <players>
```

关系target直接使用SNBT compound。例如：

```mcfunction
/pmb faction create EmpireGuard
/pmb faction create Raiders
/pmb faction rule set groupRevenge EmpireGuard 1b
/pmb faction compat set piglin guarding EmpireGuard 1b
/pmb faction relationship add EmpireGuard hostile {factions:["Raiders"]}
/pmb faction relationship add EmpireGuard allied {teams:["blue"],tags:["trusted"]}
/pmb faction relationship add EmpireGuard neutral {types:["minecraft:player"],reputation:["25.."],roles:["visitor"]}
/pmb faction member set EmpireGuard @e[type=minecraft:vindicator,distance=..16]
/pmb faction reputation set EmpireGuard @a 30
/pmb faction role add EmpireGuard @a[tag=visitor] visitor
```

设置成员时派系必须存在，选择结果必须全部为LivingEntity。关系写入会验证态度、派系、team、实体类型、实体类型标签、声望范围和列表下标。批量设置只修改当前选中的实体，不会保存或持续维护FactionMembers列表。

## PmbAi

PmbAi是本模组基础的数据根，它应当被写入生物nbt内部，并与其他基础的数据根(例如Health, Motion, equipment)属于同一层。

PmbAi是一个复合标签，内部可以包含多个手动添加的特定Ai技能，以及其参数组成的其他复合标签。

PmbAi只在生物存活时运行。生命值归零、进入死亡动画后，会立即停止新的AI检查和近战执行，并取消尚未释放的弓蓄力、举盾状态、风弹弹跳追踪及重锤执行状态；死亡动画期间不会继续攻击、投掷或射击。该停止只作用于AI与技能状态，不清除死亡击退速度，也不关闭实体重力或原版死亡流程。

默认情况下，怪物生成时不会带有PmbAi数据根。
这意味着自然生成的怪物不会有任何因为本模组导致的AI行为变化。

目前玩家必须通过data merge指令，summon指令或数据包函数来手动添加PmbAi。

### 风弹

风弹AI为持有原版风弹的生物加入投掷和弹射两种模式，也可以作为风弹重锤与后续风弹矛AI共用的基础行为。mace技能现已提供独立的下落重锤攻击检查，并可与风弹弹射后的目标保持和空中推进协同工作；风弹矛的专用攻击决策尚未实现。

风弹触发条件:

1. 实体属于生物，并且主手或副手持有原版风弹。
2. 启用(enable)为真。
3. 存在一个存活的敌对目标，或生物正在执行Faction的passively_evasive/actively_evasive逃跑并持有有效威胁目标。
4. 生物没有启用NoAI，且未处于破盾虚弱。
5. 对应模式的距离、冷却和概率检查均符合要求。

弹射模式在两个模式均可检查时优先执行。生物在bounceRange范围内且位于地面时，会每隔bounceCooldownTicks游戏刻检查一次bounceChance。检查成功后，生物会立刻低头、挥动持有风弹的手并起跳，同时向脚下发射风弹，使风弹爆炸尽可能产生向上的弹射效果。

投掷模式会在目标处于throwRange范围内且视线可见时，每隔throwCooldownTicks游戏刻检查一次throwChance。检查成功后，生物会挥动持有风弹的手，并向目标当前位置与移动速度计算出的提前量投掷风弹。throwAccuracy控制原版投射物随机散布，1.0表示无随机散布。

执行Faction逃跑时，风弹AI会把当前Faction规避目标作为风弹目标，而不会把它重新设置为攻击目标。throw模式会在释放时将视线、头部和身体短暂转向追击威胁，同时保持逃跑导航不变，随后继续逃离；bounce模式仍按bounceRange、bounceChance和bounceCooldownTicks触发脚下弹射，但弹起后的水平引导与身体朝向改为远离威胁。两个模式继续使用原有的距离、概率、冷却、精度和doConsume参数，不会因为处于evasive状态而绕过任何检查。

doConsume统一控制投掷和弹射两种模式是否消耗风弹。默认情况下，风弹仅作为技能所需的持有物，不会在触发后被消耗；启用后，每次成功投掷或弹射都会从实际挥动的手中消耗一个风弹。

脚下弹射会复用原版生物的冲量坠落保护机制。生物返回风弹弹射发生的高度时不会受到本次弹射造成的坠落伤害；如果落点低于弹射起点，超出的跌落高度仍会正常造成伤害。生物在本次弹射后确实离地并重新落到地面时，由服务端播放一次原版玩家无伤落地音；未离地、死亡或仅执行throw模式不会触发该音效。

生物被自己的风弹弹起后，会在最多60游戏刻内记住本次目标。普通战斗弹射会在原版空中寻路暂时清除目标时恢复攻击目标，并根据inAirTrackStrength施加轻微、受限的朝向目标加速度；Faction逃跑弹射不会写入攻击目标，而是使用相同强度向远离威胁的方向追加受限加速度。两者均保留重力、风弹击飞速度和原有水平惯性，不会直接覆盖为明显的追踪速度。设为0.0时不追加水平引导加速度。

低头弹射动作结束后，普通战斗弹射会在飞行期间持续将视角、头部和身体朝向目标，Faction逃跑弹射则朝向远离威胁的逃跑方向。如果生物在普通弹射的低头动作结束前发动近战攻击，则会立即结束低头姿势并面向实际攻击目标，避免未朝向敌人却完成命中的表现。朝向修正不受inAirTrackStrength影响。生物落地、目标失效或时间结束后，该空中追踪状态会清除。doConsume耗尽最后一个风弹不会提前取消已经开始的空中引导。

### 末影珍珠

末影珍珠AI使主手或副手持有原版末影珍珠的生物能够自动计算弹道并投掷。普通战斗模式以当前攻击目标为落点；执行Faction的passively_evasive或actively_evasive逃跑时，则使用远离当前规避威胁的逃生位置作为落点。

投掷检查条件:

1. 实体属于生物，并且主手或副手持有原版末影珍珠。
2. 启用(enable)为真，且throwChance大于0.0。
3. 存在一个存活的攻击目标，或生物正在执行Faction逃跑并持有有效规避威胁。
4. 普通攻击目标位于minThrowRange至maxThrowRange之间且视线可见；Faction规避威胁只需位于maxThrowRange以内且视线可见。
5. 不处于throwCooldownTicks规定的投掷检查冷却。
6. 生物没有启用NoAI，且未处于破盾虚弱。

每次满足条件时会立即进入throwCooldownTicks冷却，然后进行一次throwChance检查。因此概率检查失败同样会冷却，0游戏刻表示下一个游戏刻可以再次检查。检查成功后，生物会面向实际发射轨迹、挥动持有末影珍珠的手，并播放原版末影珍珠投掷音效。

maxThrowPower不是绝对初速度，而是原版玩家站立不动时投掷末影珍珠初速度1.5的倍率上限。默认1.0表示求解速度最高为1.5，2.0表示最高为3.0。throwAngle固定末影珍珠相对水平面的投掷仰角，默认为30度。求解器按照原版末影珍珠每刻0.99空气阻力和0.03重力进行离散模拟，在固定仰角下二分求解命中所需初速度，并根据目标最新位置与速度迭代修正提前量。所需速度超过1.5乘以maxThrowPower或该仰角不存在完整解时，仍按速度上限和指定角度投掷，允许因物理能力不足而落空。

minThrowRange与maxThrowRange控制普通战斗的投掷检查区间，使目标过近时生物不会继续反复使用珍珠；这两个参数不保证当前maxThrowPower和throwAngle能够覆盖整个物理射程。执行Faction逃跑时会忽略minThrowRange，只要规避威胁不超过maxThrowRange且视线可见即可检查。珍珠不会向威胁投掷，也不会将威胁写为攻击目标；实际落点优先使用当前逃跑导航中比当前位置更远离威胁的可达目标，并限制在maxThrowRange内，没有有效导航目标时使用稳定的直接远离位置。珍珠命中后仍执行原版末影珍珠传送、落点碰撞和伤害流程。

throwAccuracy为1.0时不添加随机散布，数值越低散布越大。doConsume为0b时，手中的末影珍珠只作为技能所需持有物，不会被消耗；为1b时，每次实际成功投掷后从挥动的手消耗一个，最后一个耗尽时显式同步空手。距离或概率检查不会提前消耗物品。

### 重锤

重锤AI使主手持有原版重锤的生物能够在下落过程中主动执行一次受概率和冷却控制的原版重锤锤击。

锤击检查条件:

1. 实体属于生物，并且主手持有原版重锤。
2. 启用(enable)为真。
3. 生物未着地，垂直速度向下，并满足原版重锤锤击所需的最低坠落距离。
4. 存在一个存活、可攻击、视线可见且进入smashRange的敌对目标。
5. 不处于smashCooldownTicks规定的锤击检查冷却。
6. 生物没有启用NoAI，且未处于破盾虚弱。

满足条件后会立刻进行一次hitChance检查。不论检查成功或失败，都会立即进入smashCooldownTicks游戏刻的冷却。检查成功时，生物会面向目标、挥动主手，并通过原版Mob攻击与重锤伤害流程执行锤击；检查失败时不发动攻击。

技能启用且生物处于有效的下落重锤状态时，普通近战Goal未经本技能检查发起的攻击会被阻止。这样原版AI不会绕过hitChance、smashCooldownTicks或damageReduction。生物不处于有效重锤下落状态时，普通近战不受影响。

锤击会先由原版计算基础攻击伤害、附魔和坠落高度提供的重锤额外伤害，再将最终结果乘以(1-damageReduction)。默认damageReduction为0.5，因此由本技能触发的最终重锤伤害减半。原版重锤命中后的声音、击退、耐久消耗和坠落状态处理仍然保留。

### 弓箭

弓箭AI仅在生物主手持有原版弓时运行，包含使用低弹道的line直射模式与使用固定高仰角的arc抛射模式。range参数只控制是否启动射击行为；箭矢是否具有足够的实际射程由power参数和原版投射物物理决定。

两个模式均要求目标存活、可攻击且视线可见。line在目标距离不大于lineRange时可检查；arc在目标距离处于arcMinRange至arcMaxRange之间时可检查。任一ShootChance为0.0时，对应模式完全关闭。

当两个模式同时满足距离、弹药且冷却就绪时，由modePriority选择line或arc。优先模式概率失败后，本游戏刻不会回退另一模式；若优先模式仍在冷却或其他检查条件不满足，则允许另一模式检查。每次选中模式后都会立刻进入对应CooldownTicks冷却，无论概率成功或失败。

概率成功后，生物使用对应ChargeTicks开始主手拉弓；0表示当刻释放。蓄力期间头部和双臂持续对准当前模式实际计算的发射向量，因此line显示低弹道瞄准，arc显示与其设计仰角一致的抬弓瞄准。目标死亡、不可攻击、离开当前模式范围、失去视线、弓离开主手、所需弹药失效、启用NoAI或进入破盾虚弱时，蓄力立即取消且已经开始的冷却保留。

linePower和arcMaxPower均为原版玩家满蓄力弓箭初速度3.0的倍率，而非绝对初速度。line模式使用3.0乘以linePower作为固定初速度，根据目标最新位置、移动速度和轻微重力补偿形成低弹道。arc模式使用arcAngle作为相对水平面的固定仰角，按原版箭矢0.99空气阻力和0.05重力数值模拟、二分求解所需初速度，并迭代修正移动目标提前量。所需速度超过3.0乘以arcMaxPower或没有完整解时，仍按该速度上限射出，因此可能因物理能力不足而落空。Accuracy为1.0时不添加随机散布。

副手有弓支持的箭矢时优先使用该箭种。doConsume为0b时不消耗箭，且副手无箭时使用无限普通箭；为1b时必须副手持有受支持箭矢，并在实际释放成功后消耗一个。最后一支箭耗尽时会显式同步空副手。弓不会额外损失耐久。

启用本技能且生物主手持弓时，所有近战攻击都会被阻止。目标处于当前模式可射击范围内时停止近战寻路；进入对应SafeDistance以内时，无论mobileWhileShooting为何值都会边后退边瞄准。arc的后退判定也适用于目标已经进入arcMinRange以内的情况，使仅启用arc的弓箭手仍能尝试重新拉开距离。目标位于SafeDistance之外但仍在模式范围内时，mobileWhileShooting为1b会进行类似骷髅的随机前后侧移，为0b则原地射击。

原版RangedBowAttackGoal的拉弓、射箭和侧移写入会被屏蔽，以避免骷髅绕过本技能的模式、概率、冷却或mobileWhileShooting；PMB自身的后退与随机游走指令仍可正常通过。拉弓姿势会在模型动画的最后阶段强制覆盖，避免僵尸或灾厄村民等模型自己的攻击、抱手动画再次覆盖双臂；卫道士和唤魔者的专用手持物品层也会显示弓和双臂。

### 盾牌

目前实现了基础的盾牌使用。
符合条件的生物会循环检查是否可以举盾，检查结果受可配置的概率影响。

举盾触发条件:

1. 实体属于生物，并且副手持有原版盾牌。
2. 启用(enable)为真。
3. 存在一个进入举盾范围(range)，存活且在视线内的敌对目标。
4. 不处于举盾冷却时间(cooldownTicks)。
5. 不处于破盾攻击造成的强制禁用时间(axeDisableCooldownTicks)。
6. 概率举盾检查(shieldChance)成功。
7. 生物没有启用NoAI。

由本模组控制的盾牌从举盾首个游戏刻起即可格挡，不使用原版玩家盾牌的初始生效延迟。

由本模组控制的盾牌会在可用时优先根据攻击者实体位置计算格挡角度，而不是只依赖原始伤害来源位置。这可以避免贴脸攻击或交互距离延长时，伤害来源位置越过防御者导致角度翻面，并表现为穿盾。

如果服务端仍认为生物正在使用副手盾牌，即使内部举盾计数刚刚归零，本模组也会在最终过渡游戏刻继续识别盾牌。

举盾后，盾牌会在成功格挡攻击时正常损失耐久。

能够禁用盾牌的攻击每次会消耗一点盾牌韧性；当前一轮受到的此类攻击次数达到配置值时，本次举盾才会中止并触发强制禁用时间。

计数会在普通冷却自然结束时刷新，在强制禁用结束、开始新一轮前刷新，并会在本次举盾未真正破盾但被中断时立即刷新。

盾牌反作用力、耐久损耗和盾牌韧性消耗在每个普通伤害间隔内最多触发一次。被实体伤害冷却忽略的额外攻击不会积累这些效果。

被盾牌完全格挡的攻击不会产生原版暴击粒子，但本模组会在玩家攻击蓄力重置前记录其是否满足原版暴击条件。

可破盾暴击会消耗critToughnessDamage点盾牌韧性；若盾牌尚未被破坏，可破盾暴击会播放僵尸敲击木门的音效并产生10个橡木门碎屑粒子，普通可破盾攻击产生6个粒子，其他任何被格挡的攻击产生3个粒子。
真正破盾时则播放僵尸摧毁木门的音效，产生24个粒子，并施加由disableKBMultiplier控制的额外破盾击退。

真正破盾后，生物会进入disableVulnerTicks游戏刻的破盾虚弱。

破盾虚弱期间，生物无法攻击，会持续清空目标和导航，并压制AI移动输入，但保留击退或其他外力造成的已有速度，同时显示类似僵尸村民被治愈或猪灵僵尸化时的抖动效果。

此机制不会启用NoAI，因此重力等正常物理效果仍然生效。此期间受到的伤害会乘以vulnerDamageMultiplier。若disableVulnerTicks为0，则跳过破盾虚弱。

为了避免与Guard Villagers模组冲突，命名空间为guardvillagers的实体不会使用本模组的盾牌行为。
