# 关于 热插拔怪物AI 的文档

## 简介

本模组引入了新的，高度自定义的，相对简单的怪物的AI行为数据结构。
该数据结构可以通过使用指令或数据包，在游戏内即时修改并生效，立刻修改或允许特定的AI行为。
可选的参数和定义数据结构的语法将在下方给出。

## PmbAi

PmbAi是本模组基础的数据根，它应当被写入生物nbt内部，并与其他基础的数据根(例如Health, Motion, equipment)属于同一层。

PmbAi是一个复合标签，内部可以包含多个手动添加的特定Ai技能，以及其参数组成的其他复合标签。

默认情况下，怪物生成时不会带有PmbAi数据根。
这意味着自然生成的怪物不会有任何因为本模组导致的AI行为变化。

目前玩家必须通过data merge指令，summon指令或数据包函数来手动添加PmbAi。

<details>
<summary>抽象结构</summary>

```text
PmbAi:
    {
        shield:{<parameters>},
        mace:{<parameters>},
        bow:{<parameters>},
        ...
    }
```

目前实现了shield、wind_charge和mace。bow只是未来可能加入的技能标签示例，目前不可用。

</details>

### 风弹

风弹AI为持有原版风弹的生物加入投掷和弹射两种模式，也可以作为风弹重锤与后续风弹矛AI共用的基础行为。mace技能现已提供独立的下落重锤攻击检查，并可与风弹弹射后的目标保持和空中推进协同工作；风弹矛的专用攻击决策尚未实现。

风弹触发条件:

1. 实体属于生物，并且主手或副手持有原版风弹。
2. 启用(enable)为真。
3. 存在一个存活的敌对目标。
4. 生物没有启用NoAI，且未处于破盾虚弱。
5. 对应模式的距离、冷却和概率检查均符合要求。

弹射模式在两个模式均可检查时优先执行。生物在bounceRange范围内且位于地面时，会每隔bounceCooldownTicks游戏刻检查一次bounceChance。检查成功后，生物会立刻低头、挥动持有风弹的手并起跳，同时向脚下发射风弹，使风弹爆炸尽可能产生向上的弹射效果。

投掷模式会在目标处于throwRange范围内且视线可见时，每隔throwCooldownTicks游戏刻检查一次throwChance。检查成功后，生物会挥动持有风弹的手，并向目标当前位置与移动速度计算出的提前量投掷风弹。throwAccuracy控制原版投射物随机散布，1.0表示无随机散布。

doConsume统一控制投掷和弹射两种模式是否消耗风弹。默认情况下，风弹仅作为技能所需的持有物，不会在触发后被消耗；启用后，每次成功投掷或弹射都会从实际挥动的手中消耗一个风弹。

脚下弹射会复用原版生物的冲量坠落保护机制。生物返回风弹弹射发生的高度时不会受到本次弹射造成的坠落伤害；如果落点低于弹射起点，超出的跌落高度仍会正常造成伤害。

生物被自己的风弹弹起后，会在最多60游戏刻内记住本次目标。若原版空中寻路暂时清除了目标，本模组会恢复该目标，并根据inAirTrackStrength在空中施加轻微、受限的朝向目标加速度，使生物在保留重力、风弹击飞速度和原有水平惯性的同时逐渐向目标推进，而不会直接覆盖为明显的追踪速度。设为0.0时不追加水平追踪加速度。

低头弹射动作结束后，生物会在飞行期间持续将视角、头部和身体朝向目标。如果生物在低头动作结束前发动近战攻击，则会立即结束低头姿势并面向实际攻击目标，避免未朝向敌人却完成命中的表现。朝向修正不受inAirTrackStrength影响。生物落地、目标失效或时间结束后，该空中追踪状态会清除。

<details>
<summary>参数细节</summary>

```text
enable
含义: 是否启用这项AI技能
传参类型: 布尔值
值域: 0b, 1b
默认值: 0b

doConsume
含义: 投掷或脚下弹射成功触发时是否消耗一个风弹
传参类型: 布尔值
值域: 0b, 1b
默认值: 0b
说明: 同时控制两种模式，并从触发时实际持有风弹的手中消耗

inAirTrackStrength
含义: 脚下弹射后，每游戏刻向目标方向追加的最大水平加速度
传参类型: 浮点数
值域: [0.0f, 1.0f]
默认值: 0.012f
说明: 仅在朝向目标的水平分速度低于内部阈值时追加；0.0禁用水平追踪，但不会禁用飞行时面向目标

含义: 可以触发投掷模式的最大目标距离，同时要求生物与目标之间存在视线
传参类型: 浮点数
值域: [0.0f, 64.0f]
默认值: 16.0f

throwChance
含义: 每次投掷检查的成功概率
传参类型: 浮点数
值域: [0.0f, 1.0f]
默认值: 0.35f

throwCooldownTicks
含义: 两次投掷概率检查之间的游戏刻
传参类型: 整数
值域: [0, 72000]
默认值: 40
说明: 0表示每个游戏刻均可检查

throwAccuracy
含义: 投掷风弹的精度；数值越高，随机散布越小
传参类型: 浮点数
值域: [0.0f, 1.0f]
默认值: 0.9f
说明: 1.0表示无随机散布

bounceRange
含义: 可以触发脚下弹射模式的最大目标距离
传参类型: 浮点数
值域: [0.0f, 64.0f]
默认值: 4.0f

bounceChance
含义: 每次脚下弹射检查的成功概率
传参类型: 浮点数
值域: [0.0f, 1.0f]
默认值: 0.35f

bounceCooldownTicks
含义: 两次脚下弹射概率检查之间的游戏刻
传参类型: 整数
值域: [0, 72000]
默认值: 40
说明: 0表示每个游戏刻均可检查
```

实体读取数据时，超出值域的参数会被自动限制到相应边界。
通常情况下，20游戏刻等于1秒。

</details>

<details>
<summary>指令示例</summary>

```text
生成一个副手持有风弹，并使用全部默认风弹参数的僵尸。

```

</details>

### 重锤

重锤AI使主手持有原版重锤的生物能够在下落过程中主动执行一次受概率和冷却控制的原版重锤锤击。

锤击检查条件:

1. 实体属于生物，并且主手持有原版重锤。
2. 启用(enable)为真。
3. 生物未着地，垂直速度向下，并满足原版重锤锤击所需的最低坠落距离。
4. 存在一个存活、可攻击、视线可见且进入smashRange的敌对目标。
5. 不处于smashCooldownTicks规定的锤击检查冷却。
6. 生物没有启用NoAI，且未处于破盾虚弱。

满足条件后会立刻进行一次hitChance检查。不论检查成功或失败，都会立即进入smashCooldownTicks游戏刻的冷却。检查成功时，生物会面向目标、挥动主手，并通过原版Mob攻击与重锤伤害流程执行锤击；检查失败时不发动攻击。

技能启用且生物处于有效的下落重锤状态时，普通近战Goal未经本技能检查发起的攻击会被阻止。这样原版AI不会绕过hitChance、smashCooldownTicks或damageReduction。生物不处于有效重锤下落状态时，普通近战不受影响。

锤击会先由原版计算基础攻击伤害、附魔和坠落高度提供的重锤额外伤害，再将最终结果乘以(1-damageReduction)。默认damageReduction为0.5，因此由本技能触发的最终重锤伤害减半。原版重锤命中后的声音、击退、耐久消耗和坠落状态处理仍然保留。

### 盾牌

目前实现了基础的盾牌使用。
符合条件的生物会循环检查是否可以举盾，检查结果受可配置的概率影响。

举盾触发条件:

1. 实体属于生物，并且副手持有原版盾牌。
2. 启用(enable)为真。
3. 存在一个进入举盾范围(range)，存活且在视线内的敌对目标。
4. 不处于举盾冷却时间(cooldownTicks)。
5. 不处于破盾攻击造成的强制禁用时间(axeDisableCooldownTicks)。
6. 概率举盾检查(shieldChance)成功。
7. 生物没有启用NoAI。

由本模组控制的盾牌从举盾首个游戏刻起即可格挡，不使用原版玩家盾牌的初始生效延迟。

由本模组控制的盾牌会在可用时优先根据攻击者实体位置计算格挡角度，而不是只依赖原始伤害来源位置。这可以避免贴脸攻击或交互距离延长时，伤害来源位置越过防御者导致角度翻面，并表现为穿盾。

如果服务端仍认为生物正在使用副手盾牌，即使内部举盾计数刚刚归零，本模组也会在最终过渡游戏刻继续识别盾牌。

举盾后，盾牌会在成功格挡攻击时正常损失耐久。

能够禁用盾牌的攻击每次会消耗一点盾牌韧性；当前一轮受到的此类攻击次数达到配置值时，本次举盾才会中止并触发强制禁用时间。

计数会在普通冷却自然结束时刷新，在强制禁用结束、开始新一轮前刷新，并会在本次举盾未真正破盾但被中断时立即刷新。

盾牌反作用力、耐久损耗和盾牌韧性消耗在每个普通伤害间隔内最多触发一次。被实体伤害冷却忽略的额外攻击不会积累这些效果。

被盾牌完全格挡的攻击不会产生原版暴击粒子，但本模组会在玩家攻击蓄力重置前记录其是否满足原版暴击条件。

可破盾暴击会消耗critToughnessDamage点盾牌韧性；若盾牌尚未被破坏，可破盾暴击会播放僵尸敲击木门的音效并产生10个橡木门碎屑粒子，普通可破盾攻击产生6个粒子，其他任何被格挡的攻击产生3个粒子。
真正破盾时则播放僵尸摧毁木门的音效，产生24个粒子，并施加由disableKBMultiplier控制的额外破盾击退。

真正破盾后，生物会进入disableVulnerTicks游戏刻的破盾虚弱。

破盾虚弱期间，生物无法攻击，会持续清空目标和导航，并压制AI移动输入，但保留击退或其他外力造成的已有速度，同时显示类似僵尸村民被治愈或猪灵僵尸化时的抖动效果。

此机制不会启用NoAI，因此重力等正常物理效果仍然生效。此期间受到的伤害会乘以vulnerDamageMultiplier。若disableVulnerTicks为0，则跳过破盾虚弱。

为了避免与Guard Villagers模组冲突，命名空间为guardvillagers的实体不会使用本模组的盾牌行为。

```text
含义: 举盾结束或举盾概率检查失败后冷却的游戏刻
传参类型: 整数
值域: [0, 400]
默认值: 40

blockingAngle
含义: 盾牌能够格挡的最大攻击角度，单位为度
传参类型: 浮点数
值域: [1.0f, 180.0f]
默认值: 30.0f

axeDisableCooldownTicks
含义: 破盾攻击导致的盾牌强制禁用游戏刻
传参类型: 整数
值域: [0, 600]
默认值: 100

shieldToughness
含义: 当前一轮举盾需要受到多少次可破盾攻击才会被破盾
传参类型: 整数
值域: [1, 100]
默认值: 1
刷新时机: 普通冷却自然结束时，以及强制禁用结束、开始新一轮前

critToughnessDamage
含义: 满足原版玩家暴击条件的可破盾攻击会消耗多少点盾牌韧性
传参类型: 整数
值域: [1, 100]
默认值: 1
说明: 普通可破盾攻击固定消耗1点；无法禁用盾牌的攻击不会消耗盾牌韧性

disableVulnerTicks
含义: 真正破盾后进入破盾虚弱的持续游戏刻
传参类型: 整数
值域: [0, 72000]
默认值: 40
说明: 0会跳过破盾虚弱

vulnerDamageMultiplier
含义: 破盾虚弱期间受到伤害的倍率
传参类型: 浮点数
值域: [1.0f, 100.0f]
默认值: 1.5f
说明: 1.5表示破盾虚弱期间受到两倍伤害

disableKBMultiplier
含义: 真正破盾的最后一击施加的额外破盾击退倍率
传参类型: 浮点数
值域: [0.0f, 100.0f]
默认值: 1.2f
说明: 0.0会禁用额外破盾击退；实际基础强度为0.6乘以该倍率

speedReduction
含义: 举盾时的移动速度衰减比例
传参类型: 浮点数
值域: [0.0f, 1.0f]
默认值: 0.5f
兼容格式: 大于1.0的值会先按百分数换算再进行限制，例如50会被换算为0.5
```

实体读取数据时，超出值域的参数会被自动限制到相应边界。
通常情况下，20游戏刻等于1秒。
