# 关于 热插拔怪物AI 的文档

## 简介

本模组引入了新的，高度自定义的，相对简单的怪物的AI行为数据结构。
该数据结构可以通过使用指令或数据包，在游戏内即时修改并生效，立刻修改或允许特定的AI行为。
可选的参数和定义数据结构的语法将在下方给出。

## 双端部署与同步

本模组构建为一个同时用于客户端和服务端的通用JAR，但公共与客户端源码已经通过Loom source set分离。专用服务端只加载公共和服务端逻辑，模型、渲染与客户端Mixin只在物理客户端加载。

客户端和服务端均必须安装本模组。连接配置阶段会交换独立的PMB网络协议号；客户端缺少本模组、服务器缺少本模组或协议不兼容时会在进入世界前断开连接并显示原因。模组显示版本不要求完全一致，只要求网络协议兼容。

AI决策、伤害和PmbAi配置始终由服务端负责。举盾、拉弓、手持物和旋转使用原版同步状态；破盾虚弱剩余时间使用SynchedEntityData同步，以便远程客户端正确显示抖动。完整PmbAi配置不会发送给客户端。

## 模块化技能测试指令

权限等级为2的管理员可以在不手写完整SNBT的情况下修改一个或多个Mob的单项技能：

```mcfunction
/pmb skills skill <targets> <skill> get
/pmb skills skill <targets> <skill> append [<parameter>=<value>,...]
/pmb skills skill <targets> <skill> insert [<parameter>=<value>,...]
/pmb skills skill <targets> <skill> modify [<parameter>=<value>,...]
/pmb skills skill <targets> <skill> delete [<parameter>,...]
/pmb skills skill <targets> <skill> delete *
/pmb skills skill <targets> <skill> delete []
```

`<skill>`会补全为`shield`、`wind_charge`、`ender_pearl`、`mace`、`bow`或`air_tracking`。`append`只创建不存在的节点，也允许用`append []`创建空节点；`insert`只加入尚未显式写入的字段；`modify`只修改已经显式写入的字段；`delete [a,b]`移除这些显式字段并恢复默认值；`delete *`保留空的默认关闭技能节点；`delete []`删除技能节点本身。`get`只接受一个Mob，显示节点是否存在、显式字段，以及全部当前有效值与其显式或默认来源。

目标选择器的结果必须全部为Mob。批量写入会先验证全部目标、操作前置条件和最终完整配置；任一目标失败时不会修改任何目标。成功写入会立即只取消所选技能，并清除其冷却与动作状态；修改shield时还会刷新盾牌剩余韧性。其他技能与冷却不受影响。

方括号解析器会在`[`和每个顶层逗号之后补全尚未使用的参数，并附带类型、值域、默认值提示及直接插入的`key=`。`=`之后会提示`0b`/`1b`、带引号的`"line"`/`"arc"`、带正确后缀的数值默认值和带引号的FetchSource来源；delete参数列表同样提示未使用字段。布尔值只接受`0b`或`1b`；整数不能含小数或后缀；浮点数必须含`f`后缀且必须为有限数；字符串必须加引号。未知或重复字段、类型错误、越界值、最终min/max关系错误、括号缺失和尾随输入都会在指令游标处报错。指令只提供区分大小写的规范字段；旧NBT别名继续兼容读取，但不会出现在指令参数中。

`FetchSource`使用带引号的字符串列表，接受`mainhand`、`offhand`、`inventory`、`inventory:n`或`inventory:a..b`，并要求`1 <= a <= b <= 256`；允许重复和重叠：

```mcfunction
/pmb skills skill @e[type=minecraft:zombie,limit=1] bow append [enable=1b,doConsume=1b,modePriority="arc",mobileWhileShooting=1b,lineMinRange=0.0f,lineMaxRange=14.0f,lineSafeDistance=6.0f,lineCooldownTicks=30,lineShootChance=0.8f,lineShootAccuracy=1.0f,lineChargeTicks=10,linePower=0.8f,arcMinRange=12.0f,arcMaxRange=64.0f,arcSafeDistance=10.0f,arcCooldownTicks=50,arcShootChance=0.6f,arcShootAccuracy=0.95f,arcChargeTicks=20,arcAngle=60.0f,arcMaxPower=1.25f]
/pmb skills skill @e[type=minecraft:zombie,limit=1] bow insert [FetchSource=["mainhand","inventory:1..9","inventory:7..16"]]
/pmb skills skill @e[type=minecraft:zombie,limit=1] bow modify [lineShootChance=1.0f]
/pmb skills skill @e[type=minecraft:zombie,limit=1] bow delete [lineShootChance,linePower]
```

## 分策略技能优先级与抢占

`26.9.17-1`加入分策略优先级列表。单个带引号的技能ID形成一个严格优先层，子列表形成同一平级层。至少两个平级候选的固定触发条件成立且冷却到期，并争夺本刻唯一提交或同一必需资源时，才形成contested set。轮换游标决定第一个概率检查；之后按顺序检查直至某项提交，后续候选不检查，且只有contested set成功提交才把游标推进到实际胜者之后。当前策略中省略的技能不能启动。`vanilla`必须且只能出现一次，作为普通战斗寻路和标准近战的边界。

```text
PmbAi:{skillPriorities:{combat:["mace","ender_pearl","wind_charge","air_tracking","bow","shield","vanilla"],retreat:["ender_pearl","wind_charge","air_tracking","vanilla"],idle:["vanilla"]}}
```

```mcfunction
/pmb skills priority @e[type=minecraft:zombie,limit=1] get all
/pmb skills priority @e[type=minecraft:zombie] set combat ["mace",["ender_pearl","bow"],"wind_charge","shield","vanilla"]
/pmb skills priority @e[type=minecraft:zombie] reset combat
/pmb skills priority @e[type=minecraft:zombie] reset all
```

<details>
<summary>仲裁与移动细节</summary>

每刻最多提交一个新动作或不可逆完成动作。技能先开始冷却并判定概率，再进入资源仲裁；只有最终复核和完整抢占计划均通过后才取消原阶段。只有严格更高层能抢占冲突的必需资源；平级不会抢占正在执行的阶段。可选资源永远不阻塞必需资源，并会逐刻重新申请。被抢占技能保留剩余冷却，不缓存，也不会自动恢复。

策略或权威目标变化会逐个复核活动阶段；仍在新策略列表中且自身有效的阶段会继续，不再无差别取消。BLOCKED、死亡、NoAI、策略省略或阶段自身失效仍会取消。原版标准近战会最终复核当前近战距离与感知视线。物品、绑定和弹药只读计划会在抢占前完成；此后理论上不应发生的提交失败会终止本刻，并在已经取消旧阶段时显示为`COMMIT_FAILED_AFTER_PREEMPT`。

`NAVIGATION`是唯一的主动移动决策资源，明确站桩同样属于移动决策。弓在站桩、后退和游走时均持有该资源；独立`air_tracking`必需占用`NAVIGATION`、可选`LOOK`；重锤本身不占用`NAVIGATION`，因此保留风弹重锤组合。`vanilla`只涵盖普通Goal/Brain战斗移动与标准近战，不包括特殊攻击、远程攻击、法术、爆炸或光束。

</details>

<details>
<summary>稀疏技能数据与兼容性</summary>

技能compound现在使用稀疏保存：实际存在的子节点及其中按规范顺序出现的字段分别定义节点存在性与显式字段。空节点、部分配置、直接写入的`/summon`数据以及后续`/data merge`或`/data remove`修改都能跨保存和重载保持语义。旧的完整compound会把每个实际存在的规范字段视为显式字段；受支持的旧别名会在读取时映射为对应规范字段。

</details>

## 技能调试探针

客户端默认按键`K`可在控制设置的“输出PMB技能调试快照”中重新绑定。管理员将准星对准实体并按一次按键时，客户端只发送一次实体编号请求。服务端只接受权限等级2的玩家请求，并验证目标是同一维度、位于玩家实体交互距离以内且有视线的Mob，同时要求该Mob实际具有已配置的PmbAi技能。每名玩家的请求间隔至少为250毫秒。同一份报告会写入服务端控制台和日志，并以一条多行原版系统消息只显示在请求玩家的聊天栏中；报告不向其他玩家广播，不使用自定义S2C调试负载，也不会向客户端同步完整PmbAi配置。

报告是上一完整PMB技能刻的不可变副本，并显示`ageTicks`。实体信息之后依次显示`MELEE`、`PRIORITY`、`ACTIVE PHASES`、`LAST PREEMPTION`、`SKILLS`、`LAST ATTEMPTS`、`RESOURCES`、`BINDINGS`和`CONTEXT`，让普通近战压制成为紧随实体信息的最高优先警告。`PRIORITY`显示唯一策略、优先级来源是默认值还是实体覆盖，以及最终生效的层级；`ACTIVE PHASES`分别列出必需与可选资源，`LAST PREEMPTION`标识最近一次阶段交接。`SKILLS`只列出最终`enable`值为true的技能；已经配置但关闭以及未配置的技能都会隐藏。每个显示的技能包含正在执行/等待状态、冷却及相关运行状态。其余区块包含候选尝试结果、持续与最终资源owner、动作绑定、权威目标、原版实际使用手，以及独立移动裁决实际应用的游走/硬停止/速度修正。

空区块仍会明确显示为`ACTIVE PHASES: []`、`SKILLS: []`、`LAST ATTEMPTS: []`、`RESOURCES: {}`和`BINDINGS: []`，避免把空结果误认为报告被截断。没有发生过抢占时，`LAST PREEMPTION`在服务端日志中显示`none`、在聊天栏显示`-`。服务端日志保持稳定的英文技术文本；聊天栏标题和状态标签由接收客户端按语言本地化，并以不同颜色区分正在执行/成功、等待、阻塞/压制、次要细节和标题，技能ID与诊断字段名则保持技术形式。

`activeThisTick`表示该技能在记录刻开始时拥有持续资源，或其获准候选在该刻抵达了真实执行点。候选结果区分`PRECLAIM_REJECTED`、附带阻塞资源与owner的`RESOURCE_BLOCKED`、`ADMITTED+FINAL_REJECTED`、`COMMIT_FAILED`、`COMMIT_FAILED_AFTER_PREEMPT`以及`ADMITTED+EXECUTED`。风弹状态还会显示追踪为inactive、infinite或剩余刻数，并显示最近清除原因。探针只观察已经完成的结果，不会再次执行概率、最终条件、资源裁决、物品交换或动作。已配置但尚无完整快照的Mob会在日志中输出`SNAPSHOT: unavailable`，聊天栏显示对应的本地化文本。

## 动态Faction派系

Faction是独立于PmbAi技能的服务端动态关系模块。玩家和所有LivingEntity均可加入一个派系，但不能同时属于两个派系。成员身份保存在实体根NBT中：

```text
PmbFaction:{
    FactionName:"EmpireGuard"
}
```

FactionName是区分大小写的普通字符串，不受Minecraft资源ID的`namespace:path`和小写限制。指令中直接输入不含空白的名称，不需要添加引号，例如`EmpireGuard`、`北方联盟`或`Raiders-02`。FactionName必须对应已经创建的服务端派系。删除派系会清除已加载成员；未加载成员在下次加载时清除失效名称。玩家死亡重生后保留成员身份。

PmbFaction不是客户端显示用的临时数据，而是由服务端读取和保存的实体持久NBT；完整成员关系不会同步给客户端。可以在生成实体时直接写入，无需先生成再使用选择器：

```mcfunction
/pmb faction create 灾厄庭
/summon minecraft:vindicator ~ ~ ~ {PmbFaction:{FactionName:"灾厄庭"}}
/summon minecraft:pillager ~ ~ ~ {PmbFaction:{FactionName:"灾厄庭"},PmbAi:{bow:{enable:1b}},equipment:{mainhand:{id:"minecraft:bow"}}}
/data merge entity @e[type=minecraft:vindicator,sort=nearest,limit=1] {PmbFaction:{FactionName:"灾厄庭"}}
```

`/summon`只写入成员身份，不会自动创建派系；对应派系必须已经存在于服务端SavedData中，且FactionName必须大小写完全一致。不存在的名称会在实体的下一个服务端tick被清除。数据包函数可以先创建派系，再在同一函数中直接执行带PmbFaction的summon。

派系定义保存在服务端主世界SavedData中并由所有维度共享，不会把完整规则同步给客户端：

```text
Factions:{
    "EmpireGuard":{
        Rules:{
            allowInternalConflict:0b,
            allowFriendlyFire:1b,
            groupRevenge:0b,
            overrideTeamRules:1b,
            defaultAttitude:"neutral",
            evasiveSpeedMultiplier:1.25f
        },
        VanillaCompatRules:{
            piglin:{
                greed:1b,
                guarding:1b,
                avoidance:1b
            },
            breeze:{
                windChargeNoAnger:1b
            }
        },
        Relationships:[
            {
                attitude:"hostile",
                target:{
                    factions:["Raiders"],
                    teams:["red"],
                    types:["minecraft:zombie","#minecraft:undead"],
                    tags:["traitor"],
                    reputation:["1..100"],
                    roles:["guard"]
                }
            }
        ],
        Players:{
            "<uuid>":{
                reputation:0,
                roles:["guard"]
            }
		}
	}
}
```

### Rules

- `allowInternalConflict`：默认`0b`。关闭时同派系成员固定按allied处理；开启后Relationships和defaultAttitude可以使同派系成员敌对或逃避。
- `allowFriendlyFire`：默认`1b`。设为`0b`时，由受击方派系阻止member或allied造成的近战、投射物和有责任者爆炸伤害。环境伤害不受影响。
- `groupRevenge`：默认`0b`。启用后，member或单向allied对象受击会使附近成员使用各自FOLLOW_RANGE反击责任者；不会反击另一个member或allied。
- `overrideTeamRules`：默认`1b`。启用时Faction可以覆盖原版team对同队索敌、反击和友伤的限制；关闭时同team关系优先遵守原版规则。
- `defaultAttitude`：默认`"neutral"`。控制没有匹配任何Relationship的目标。
- `evasiveSpeedMultiplier`：默认`1.25f`，值域`[0.0f,100.0f]`。控制两种逃跑行为使用的导航速度倍率。

### VanillaCompatRules

VanillaCompatRules与Rules、Relationships平级，专门控制Faction如何保留各类原版Brain生物的物种特色。内部先按生物分组，再填写该生物的兼容规则；缺少整个集合、缺少生物组或缺少单项时均使用默认值。当前支持：

- `piglin.greed`：默认`1b`。保留普通猪灵拾取、欣赏和交易黄金的行为；关闭时阻止新的黄金拾取或欣赏，并清理相关Brain记忆。
- `piglin.guarding`：默认`1b`。允许neutral普通猪灵保留打开受保护容器、破坏金块等原版事件产生的ANGRY_AT并发起攻击；关闭后neutral仍可在实际受击时反击。
- `piglin.avoidance`：默认`1b`。保留普通猪灵对僵尸猪灵等僵尸化生物及其他原版AVOID_TARGET的规避；该兼容规则高于Faction hostile，因此启用时不会把原版要求规避的目标设为Faction战斗目标。设为`0b`后压制原版规避，此时派系hostile可以使猪灵主动攻击僵尸猪灵。passively_evasive和actively_evasive产生的PMB规避不受此项影响。
- `breeze.windChargeNoAnger`：默认`1b`。原版风弹伤害命中`#minecraft:no_anger_from_wind_charge`内的实体时会特意跳过`lastHurtByMob`记录；PMB会在伤害已成功接受后使用伤害源已有的合法LivingEntity owner进行neutral反击补偿，但该规则启用时仍保留旋风人风弹不激怒的原版特性。其他合法LivingEntity发射的风弹可以触发neutral反击；设为`0b`后，合法的旋风人来源也可以触发。补偿只适用于该原版标签内且已加入有效Faction的Mob，仍要求责任者存活、可攻击、位于受击者自身FOLLOW_RANGE以内，并且实时态度为neutral；通用的`#minecraft:no_anger`伤害类型标签始终优先并关闭该补偿。不会凭空生成owner，也不改变groupRevenge及其他伤害类型。

猪灵蛮兵对PMB目标的合法性兼容属于防止Brain状态循环的必要修复，不是可关闭的特色行为，因此不放入piglin组。后续生物会以`hoglin:{...}`、`warden:{...}`等独立组加入，不会把不同生物的字段混在同一级。

灾厄村民的Faction战斗兼容同样不改变非战斗状态的原版特色行为。掠夺者和卫道士获得有效Faction战斗目标时，会暂时退出巡逻队原版“原地警戒并等待目标靠近”的HoldGround行为；正在寻路返回袭击或回收袭击旗帜的Raider也会先进入Faction战斗。目标失效后，这些原版行为仍可按原条件重新启动。唤魔者原版没有主动接近敌人的战斗Goal，因此会在非施法阶段接近Faction目标至16格以内，再继续使用原版唤魔与尖牙施法；该行为不提供新的伤害方式。

### Relationships和态度

Relationships按列表顺序检查，最后一条匹配规则生效。单个target中所有非空类别之间为AND；同一数组内的多个值为OR。空target不允许写入。

- `factions`匹配目标唯一的FactionName；`teams`匹配原版记分板team名称。
- `types`接受实体类型ID或以`#`开头的实体类型标签；`tags`匹配实体的`/tag`。
- `reputation`接受精确值`"5"`、上界`"..100"`、下界`"1.."`和闭区间`"1..100"`。
- `reputation`与`roles`只匹配玩家，并读取目标玩家在规则所属派系中的Players记录；玩家不需要加入该派系即可拥有记录。

五种态度的固定语义：

- `hostile`：在自身FOLLOW_RANGE内发现可见目标后主动索敌；暂时失去视线仍可继续追击，离开范围后清除目标。
- `neutral`：不主动索敌，受到有效攻击后允许反击。`VanillaCompatRules.piglin.guarding:1b`时，猪灵打开受保护容器、破坏金块等原版事件产生的ANGRY_AT属于保留的物种特有被动敌意，也可以触发攻击。对于原版风弹不激怒标签内的受击者，`VanillaCompatRules.breeze.windChargeNoAnger`控制旋风人owner是否继续保留该例外；其他合法LivingEntity owner仍可触发PMB neutral反击。
- `allied`：不主动索敌且不反击；是否阻止实际伤害由受击方allowFriendlyFire决定。
- `passively_evasive`：受到攻击后开始逃跑，直到攻击者离开自身FOLLOW_RANGE。
- `actively_evasive`：可见目标进入自身FOLLOW_RANGE时主动逃跑，目标离开范围后停止。

Faction的扫描、反击、已有目标验证和猪灵专用Brain目标解析均会排除死亡实体，以及处于创造或旁观模式的玩家。即使此类玩家攻击成员，也不会被写入Faction战斗或规避目标。猪灵、猪灵蛮兵与疣猪兽的原版受击反击入口同样会在非生存模式攻击者处停止，避免原版Brain与Faction目标反复争夺而出现举起武器、放下武器和怒吼循环。

Faction态度覆盖成员的原版主动敌意，同时管理普通Mob目标和Brain的ATTACK_TARGET/AVOID_TARGET。对Goal生物，PMB会在原版targetSelector完成后、攻击与移动goalSelector运行前重新确认Faction目标，避免原版较短的索敌距离清除FOLLOW_RANGE内的远距离目标；PMB不会因此新增通用近战Goal。仅在Brain注册了对应MemoryModule时才读取记忆，并且仅在目标变化时写入；Faction不会无条件清除未由PMB持有的原版AVOID_TARGET。猪灵和猪灵蛮兵使用专用兼容层，使PMB战斗目标通过原版目标合法性检查，同时保留neutral猪灵由原版ANGRY_AT驱动的守卫与贪婪行为。灾厄巡逻队的HoldGround、袭击寻路和旗帜回收不会压住更高优先级的Faction战斗；没有原版接近Goal的唤魔者只获得进入原版施法有效距离所需的专用导航，不获得新攻击。hostile只提供目标，不会为没有攻击行为的生物凭空添加近战技能。两种evasive复用已经指向远离威胁方向的有效导航路径；需要重新寻路时优先选择生物寻路系统确认可达的远离位置。地面寻路失败时不会把移动控制器直接指向墙内或其他不可达坐标，飞行与水生导航仍可使用稳定的直接远离移动。

## 技能调度与PmbInventory

所有PMB技能由一个服务端Mob游戏刻入口统一调用。存在Faction规避威胁时策略为`retreat`，否则存在有效攻击目标时为`combat`，没有权威目标时为`idle`。破盾虚弱、NoAI和死亡会阻止新动作；策略或权威目标改变时会逐个复核持续阶段，仍在新策略中列出且自身有效的阶段继续，省略或失效的阶段结束。

优先级、平级轮换、抢占和每刻最多一次提交均使用上文定义的持久化分策略`skillPriorities`模型。技能先掷概率并开始检查冷却，再进入资源仲裁；最终资源或条件复核失败时保留本次冷却，但不移动物品、不缓存动作，也不会在下次正常检查前重试。

风弹仍优先检查bounce，且仅在bounce概率失败时于同刻继续检查throw。弹射后的空中移动属于独立`air_tracking`：它必需占用`NAVIGATION`、可选占用`LOOK`，但不占用手、USE_ITEM或SMASH。

每项技能均可选填有序字符串列表`FetchSource`，支持`mainhand`、`offhand`、`inventory`、`inventory:1`及`inventory:1..9`等闭区间。公开库存格从1编号到256，条目和区间允许重叠。先确定本次使用手；该手已有正确物品时直接使用，不检查FetchSource。否则按列表顺序、区间内按格号升序取物。省略来源列表时使用原来的来源手顺序；显式空或无效列表不提供可取物来源，但不阻止直接使用目标手已有物品。

bow、shield、wind_charge和ender_pearl支持`preferredHand`：`main`、`off`、`main-enforce`、`off-enforce`。bow默认main，其余三项默认off；mace不支持该参数，固定主手执行。普通main/off只在动作开始时，因首选手被持续PMB动作占用而尝试另一手；静态物品不会使手不可用。enforce指定手被占用时本次失败。同刻候选竞争失败不会改手重试。

来源手或目标手被持续动作占用时不能交换，来源不可用则继续扫描。跨手交换当刻占用两手，随后持续动作只绑定实际使用手。每次检查只选择一件物品；目标手已有正确物品时不会追逐来源中另一件同类物品。

所有技能的成功换装永久保留：完成、取消、NoAI、卸载、转换和死亡都不自动换回。ActionBinding只校验当前动作物品并绑定使用手，结束后释放。接受被挤出的武器或弹药落入其FetchSource/AmmoSource之外；配置者负责范围覆盖。最终在手上的物品使用原版装备掉落规则，库存物品使用PMB库存掉落规则。

`NAVIGATION`是排他的PMB移动决策资源，明确包含站桩。弓蓄力与独立空中追踪只在各自有效的活动阶段占用它；普通Goal/Brain移动由`vanilla`表示。破盾虚弱压制AI移动但保留重力与击退。移动归属和阶段有效性逐刻复核；失去移动资源不会退款或推进技能冷却。

`PmbInventory`只属于Mob生物，并独立于`PmbAi`：

```text
PmbInventory:{
    Slots:<int>,
    DropChance:<float>,
    ScatterDrops:<bool>,
    Items:[
        {Slot:<int>,id:<物品ID>,count:<int>}
    ]
}
```

`Slots`值域为`[0,256]`、默认0；底层容器按实际`Slots`容量分配，因此`Slots:0`不会分配库存格。`DropChance`值域为`[0.0f,1.0f]`、默认0.5f。死亡时每个已启用且非空的格子独立检查一次，成功则掉落该格的完整堆叠；`doMobLoot:false`时额外库存不掉落。缩小`Slots`会先尝试把高位物品合并或移动到启用的低位格，装不下的完整剩余物会立刻掉出。1–256以外的无效格号会被忽略。原有0–27格数据可直接加载；若将使用第28–256格的数据降级到旧版PMB，这些高位物品会丢失。

`ScatterDrops`为布尔值，默认`0b`。`0b`保持原有PMB原地死亡掉落；`1b`仅将已通过`doMobLoot`限制和该格`DropChance`检查的完整堆叠交给原版玩家死亡掉落路径，从`eyeY - 0.3`附近以`[0.0,0.5)`的随机径向水平速度和`0.2`的竖直速度飞散，并使用40刻拾取延迟。该选项不损坏、不拆分堆叠，也不影响缩容/加载溢出或手持装备。

当`CanPickUpLoot:1b`且`mobGriefing:true`时，原版装备逻辑与物种专用拾取逻辑先运行；仍留在地上的近距离物品随后像玩家背包一样合并进PmbInventory，库存满时剩余物继续留在地上。该功能不会增加主动寻找物品的导航，也不提供GUI。

弓省略`AmmoSource`时，受支持弹药先检查两只手，再从PmbInventory最低的已启用格开始向后检查，找到第一个兼容堆叠便停止；显式`AmmoSource`则只按其自身有序位置扫描。弹药会被直接读取，不需要额外换到另一只手。`doConsume:0b`时优先使用真实特殊箭但不消耗，没有箭则使用无限普通箭；`doConsume:1b`时必须存在真实兼容弹药，并只在成功释放后扣除一个。

示例：

```text
summon zombie ~ ~ ~ {CanPickUpLoot:1b,PmbInventory:{Slots:9,DropChance:0.5f,ScatterDrops:1b,Items:[{Slot:1,id:"minecraft:mace",count:1},{Slot:2,id:"minecraft:wind_charge",count:16}]},PmbAi:{mace:{enable:1b,FetchSource:["mainhand","inventory:1..9"]},wind_charge:{enable:1b,FetchSource:["offhand","inventory:1..9"],doConsume:1b}}}
```

技能检查冷却随实体保存，重载时扣除经过的世界时间。持续动作不恢复，但永久装备布局正常保存。旧PmbSwapJournal仅在加载时校验完整交换并恢复一次；不覆盖已变化的槽位，不创建新的恢复日志或待恢复租约。

## PmbAi

PmbAi是本模组基础的数据根，它应当被写入生物nbt内部，并与其他基础的数据根(例如Health, Motion, equipment)属于同一层。

PmbAi是一个复合标签，内部可以包含多个手动添加的特定Ai技能，以及其参数组成的其他复合标签。

PmbAi只在生物存活时运行。生命值归零、进入死亡动画后，会立即停止新的AI检查和近战执行，并取消尚未释放的弓蓄力、举盾状态、风弹弹跳追踪及重锤执行状态；死亡动画期间不会继续攻击、投掷或射击。该停止只作用于AI与技能状态，不清除死亡击退速度，也不关闭实体重力或原版死亡流程。

五项动作技能`shield`、`wind_charge`、`ender_pearl`、`mace`和`bow`都提供整数参数`randomCooldownBias`，范围为`[0, 1200]`，默认`20`。每次检查开始冷却时，实际冷却等于基础冷却加上一个在`[0, randomCooldownBias]`内独立、均匀抽取的整数；设为`0`即可恢复固定冷却。`air_tracking`没有检查冷却。

满足条件的技能检查会先开始本次冷却并判定概率，再进入资源竞争。概率`0.0`必定失败，`1.0`必定成功，且两个端点不消耗随机数。概率失败不占用任何动作资源；概率成功后即使资源不可用或最终目标/物品复核失败，也保留本次冷却，不缓存，也不会在下次正常检查前重试。物品只在动作赢得资源后交换或消耗。弓选定的模式失败后不回退另一模式；风弹只在bounce概率失败时于同刻检查throw，bounce概率成功后的后续失败不会回退。

默认情况下，怪物生成时不会带有PmbAi数据根。
这意味着自然生成的怪物不会有任何因为本模组导致的AI行为变化。

目前玩家必须通过data merge指令，summon指令或数据包函数来手动添加PmbAi。

<summary>抽象结构</summary>

```text
PmbAi:
    {
        shield:{<parameters>},
        air_tracking:{<parameters>},
        mace:{<parameters>},
        bow:{<parameters>},
        ...
    }
```

目前实现了shield、wind_charge、ender_pearl、mace、bow和air_tracking。

### 空中追踪

`air_tracking`是独立的移动技能。只有启用的列出来源提供有效上下文时，它才开始空中追踪；`activationSkills`中第一个有效ID获胜。默认来源会让风弹弹射跨越上升与下落持续追踪，并在适用时让自然下落的重锤在完整FOLLOW_RANGE内提供追踪。它保留竖直速度，向目标施加水平加速，并仅在可选`LOOK`可用时转头。

<summary>高级生命周期与调度行为</summary>

风弹弹射属于锁存来源：成功弹射后先等待下一次空中控制刻，即使风弹的瞬时动作已经结束，仍会跨越上升和下落保持有效。锁存的弹射目标不会被之后原版/Faction的索敌改写；只有下一次成功弹射替换它，或该目标自身生命周期失效时才会失效。重锤属于条件来源：启用且可用的重锤、正在下落的Mob、当前权威目标以及完整FOLLOW_RANGE内距离都会提供来源，包括已经进入`smashRange`时。其他列出的已注册技能属于通用来源，仅在自身持续scheduler phase有效时提供。更高顺序的有效来源会立刻接管；其失效后，较低来源会在下一刻重新检查。

</details>

### 风弹

风弹AI为持有原版风弹的生物加入投掷和弹射两种模式，也可以作为风弹重锤与后续风弹矛AI共用的基础行为。mace技能现已提供独立的下落重锤攻击检查，并可与风弹弹射后的目标保持和空中推进协同工作；风弹矛的专用攻击决策尚未实现。

<details>
<summary>触发、行为与兼容性细节</summary>

风弹触发条件:

1. 实体属于生物，并且主手或副手持有原版风弹。
2. 启用(enable)为真。
3. 存在一个存活的敌对目标，或生物正在执行Faction的passively_evasive/actively_evasive逃跑并持有有效威胁目标。
4. 生物没有启用NoAI，且未处于破盾虚弱。
5. 对应模式的距离、冷却和概率检查均符合要求。

弹射模式在两个模式均可检查时优先执行。生物在bounceRange范围内且位于地面时，会每隔bounceCooldownTicks游戏刻检查一次bounceChance。检查成功后，生物会立刻低头、挥动持有风弹的手并起跳，同时向脚下发射风弹，使风弹爆炸尽可能产生向上的弹射效果。

投掷模式会在目标处于throwRange范围内且视线可见时，每隔throwCooldownTicks游戏刻检查一次throwChance。检查成功后，生物会挥动持有风弹的手，并向目标当前位置与移动速度计算出的提前量投掷风弹。throwAccuracy控制原版投射物随机散布，1.0表示无随机散布。

执行Faction逃跑时，风弹AI会把当前Faction规避目标作为风弹目标，而不会把它重新设置为攻击目标。throw模式会在释放时将视线、头部和身体短暂转向追击威胁，同时保持逃跑导航不变，随后继续逃离；bounce模式仍按bounceRange、bounceChance和bounceCooldownTicks触发脚下弹射，但弹起后的水平引导与身体朝向改为远离威胁。两个模式继续使用原有的距离、概率、冷却、精度和doConsume参数，不会因为处于evasive状态而绕过任何检查。

doConsume统一控制投掷和弹射两种模式是否消耗风弹。默认情况下，风弹仅作为技能所需的持有物，不会在触发后被消耗；启用后，每次成功投掷或弹射都会从实际挥动的手中消耗一个风弹。

脚下弹射会复用原版生物的冲量坠落保护机制。生物返回风弹弹射发生的高度时不会受到本次弹射造成的坠落伤害；如果落点低于弹射起点，超出的跌落高度仍会正常造成伤害。生物在本次弹射后确实离地并重新落到地面时，由服务端播放一次原版玩家无伤落地音；未离地、死亡或仅执行throw模式不会触发该音效。

风弹弹起后的空中追踪由独立`air_tracking`控制，而非风弹字段；耗尽最后一个风弹不会取消已锁存会话。

处于地面的bounce仍保留启动后的两个游戏刻宽限。进入第一个满足落地终止边界的游戏刻时，它会在调度器资源仲裁以及姿势或视线写入之前释放LOOK，因此已经结束的bounce不会阻止另一个原本有效的技能检查。

</details>

### 末影珍珠

末影珍珠AI使主手或副手持有原版末影珍珠的生物能够自动计算弹道并投掷。普通战斗模式以当前攻击目标为落点；执行Faction的passively_evasive或actively_evasive逃跑时，则使用远离当前规避威胁的逃生位置作为落点。

<details>
<summary>触发、弹道与逃跑细节</summary>

投掷检查条件:

1. 实体属于生物，并且主手或副手持有原版末影珍珠。
2. 启用(enable)为真，且throwChance大于0.0。
3. 存在一个存活的攻击目标，或生物正在执行Faction逃跑并持有有效规避威胁。
4. requireEyeSight为1b时，普通攻击目标需位于minThrowRange至maxThrowRange之间且视线可见；Faction规避威胁需位于maxThrowRange以内且视线可见。为0b时只跳过这一视线要求。仅对原版TargetGoal，0b还可在目标已被取得后、目标存活且处于同一世界、位于FOLLOW_RANGE和此战斗投掷范围内、throwChance大于0.0、且FetchSource可将珍珠解析到任一手时，隔墙保留mob.getTarget()；绝不改变初次索敌。
5. 不处于throwCooldownTicks规定的投掷检查冷却。
6. 生物没有启用NoAI，且未处于破盾虚弱。

每次满足条件时会立即进入throwCooldownTicks冷却，然后进行一次throwChance检查。因此概率检查失败同样会冷却，0游戏刻表示下一个游戏刻可以再次检查。检查成功后，生物会面向实际发射轨迹、挥动持有末影珍珠的手，并播放原版末影珍珠投掷音效。

maxThrowPower不是绝对初速度，而是原版玩家站立不动时投掷末影珍珠初速度1.5的倍率上限。默认1.0表示求解速度最高为1.5，2.0表示最高为3.0。throwAngle固定末影珍珠相对水平面的投掷仰角，默认为30度。求解器按照原版末影珍珠每刻0.99空气阻力和0.03重力的离散弹道，在固定仰角下二分求解命中所需初速度，并仅对目标水平移动迭代修正提前量，保持当前眼部高度。几何可达但1.5乘以maxThrowPower不足时，仍按上限投掷，允许落点不足。固定仰角几何不可达、水平距离接近零或数值求解无效时跳过投掷，不消耗珍珠，保留正常检查冷却。计算不再具有300刻弹道截断。

末影珍珠发射点（眼部下方0.1格）浸入水中时禁止投掷；浅水中该点露出实际流体表面时仍可使用。战斗与规避模式均会在提交投掷前和实际释放前检查。

minThrowRange与maxThrowRange控制普通战斗的投掷检查区间，使目标过近时生物不会继续反复使用珍珠；这两个参数不保证当前maxThrowPower和throwAngle能够覆盖整个物理射程。执行Faction逃跑时会忽略minThrowRange；requireEyeSight为1b时，只要规避威胁不超过maxThrowRange且视线可见即可检查，为0b时只跳过这一视线要求。珍珠不会向威胁投掷，也不会将威胁写为攻击目标；实际落点优先使用当前逃跑导航中比当前位置更远离威胁的可达目标，并限制在maxThrowRange内，没有有效导航目标时使用稳定的直接远离位置。珍珠命中后仍执行原版末影珍珠传送、落点碰撞和伤害流程。

throwAccuracy为1.0时不添加随机散布，数值越低散布越大。doConsume为0b时，手中的末影珍珠只作为技能所需持有物，不会被消耗；为1b时，每次实际成功投掷后从挥动的手消耗一个，最后一个耗尽时显式同步空手。距离或概率检查不会提前消耗物品。

</details>

### 重锤

重锤AI固定使用主手。主手已有原版重锤时直接使用，否则从FetchSource永久换入；副手来源的交换当刻占用双手和SMASH。重锤只在下落、目标与概率冷却条件满足时执行，不接受preferredHand。

<details>
<summary>触发与伤害细节</summary>

锤击检查条件:

1. 实体属于生物，并且FetchSource可将原版重锤解析到所需的主手攻击路径。
2. 启用(enable)为真。
3. 生物未着地，垂直速度向下，并满足原版重锤锤击所需的最低坠落距离。
4. 存在一个存活、可攻击、视线可见且进入smashRange的敌对目标。
5. 不处于smashCooldownTicks规定的锤击检查冷却。
6. 生物没有启用NoAI，且未处于破盾虚弱。

满足条件后会立刻进行一次hitChance检查。不论检查成功或失败，都会立即进入smashCooldownTicks游戏刻的冷却。检查成功时，生物会面向目标、挥动主手，并通过原版Mob攻击与重锤伤害流程执行锤击；检查失败时不发动攻击。

技能启用且生物处于有效的下落重锤状态时，普通近战Goal未经本技能检查发起的攻击会被阻止。这样原版AI不会绕过hitChance、smashCooldownTicks或damageReduction。生物不处于有效重锤下落状态时，普通近战不受影响。

锤击会先由原版计算基础攻击伤害、附魔和坠落高度提供的重锤额外伤害，再将最终结果乘以(1-damageReduction)。默认damageReduction为0.5，因此由本技能触发的最终重锤伤害减半。原版重锤命中后的声音、击退、耐久消耗和坠落状态处理仍然保留。

</details>

### 弓箭

弓箭AI由preferredHand选择使用手，默认main。该手已有原版弓时直接使用，否则从FetchSource永久换入。弓仍属于main类别，但持续拉弓只占实际使用手、USE_ITEM和LOOK。该技能包含低弹道line与高仰角arc模式；range控制射击检查距离，power和原版物理决定实际射程。

<details>
<summary>触发、弹药、移动与渲染细节</summary>

两个模式均要求目标存活且可攻击。requireEyeSight为1b时还要求视线可见；为0b时只跳过这一视线要求。仅对原版TargetGoal，0b还可在目标已被取得后、目标存活且处于同一世界、位于FOLLOW_RANGE和已启用line或arc的射击范围内、且按目标手和FetchSource规则可取得弓时，隔墙保留mob.getTarget()；绝不改变初次索敌。此规则仅作用于TargetGoal，不影响Faction或Brain索敌、任何规避路径（包括珍珠规避）、通用近战或其他技能。line在目标距离处于lineMinRange至lineMaxRange之间时可检查；arc在目标距离处于arcMinRange至arcMaxRange之间时可检查。任一ShootChance为0.0时，对应模式完全关闭。

当两个模式同时满足距离、弹药且冷却就绪时，由modePriority选择line或arc。优先模式概率失败后，本游戏刻不会回退另一模式；若优先模式仍在冷却或其他检查条件不满足，则允许另一模式检查。每次选中模式后都会立刻进入对应CooldownTicks冷却，无论概率成功或失败。

概率成功后，生物使用对应ChargeTicks开始用解析到的手拉弓；0表示当刻释放。蓄力期间头部和双臂持续对准当前模式实际计算的发射向量，因此line显示低弹道瞄准，arc显示与其设计仰角一致的抬弓瞄准。目标死亡、不可攻击、离开当前模式范围、requireEyeSight为1b时失去视线、弓离开当前使用手、所需弹药失效、启用NoAI或进入破盾虚弱时，蓄力立即取消且已经开始的冷却保留。

linePower和arcMaxPower均为原版玩家满蓄力弓箭初速度3.0的倍率，而非绝对初速度。line模式使用3.0乘以linePower作为固定初速度，根据目标最新位置、移动速度和轻微重力补偿形成低弹道。arc模式使用arcAngle作为相对水平面的固定仰角，按原版箭矢0.99空气阻力和0.05重力数值模拟、二分求解所需初速度，并迭代修正移动目标提前量。所需速度超过3.0乘以arcMaxPower或没有完整解时，仍按该速度上限射出，因此可能因物理能力不足而落空。Accuracy为1.0时不添加随机散布。

`AmmoSource`独立限制弓箭AI读取真实受支持箭矢的位置，使用与FetchSource相同的有序来源语法，但绝不移动或交换弹药。省略时保留原有行为：两只手中的受支持箭矢优先，其次从已启用PmbInventory低位到高位寻找。显式列表只按书写顺序扫描其中的位置；字段存在但为空或无效时不存在真实弹药来源。弓换装挤出此前选中的手持箭矢时，本次动作跟踪箭堆到另一只手或库存格并在真实位置扣除。下一动作重新严格扫描AmmoSource；不单独交换弹药，也不保留长期范围豁免。doConsume为0b时不消耗弹药，没有真实箭时使用无限普通箭；为1b时必须存在真实受支持箭矢，并在实际释放成功后从真实来源消耗一个。弓不会额外损失耐久。FetchSource只解析弓本身，绝不限制本次弹药查询。

普通近战只由轻量实时条件压制：bow已启用；当前目标非空、存活、同世界且可以攻击；弓已经实际位于允许的手中；目标距离位于至少一个ShootChance大于0的line或arc闭区间；doConsume为1b时AmmoSource仍能找到受支持箭矢。普通main/off偏好允许弓已在任一手，main-enforce和off-enforce则只接受指定手。库存弓、FetchSource可取弓和动作binding均不算实际手持。冷却、本轮概率、资源claim、视线/requireEyeSight、modePriority、SafeDistance、mobileWhileShooting和FOLLOW_RANGE都不参与这项实时判定。任何必要条件失效时，原版近战Goal导航和普通直接近战伤害会立即恢复。FetchSource仍只负责启动技能和换入弓，不会单独压制近战。K键报告的`bow`压制原因使用同一个predicate。

调度器选中的PMB重锤下落锤击仍允许通过，因此有效的弓近战压制不会取消合法的风弹/重锤等组合。弓箭只在一次成功检查已获得所需动作资源、绑定弓并开始拉弓后接管移动。在该拉弓期间，进入对应SafeDistance以内会使生物边后退边瞄准，不受mobileWhileShooting开关影响。目标位于SafeDistance之外但仍在模式范围内时，mobileWhileShooting为1b会进行类似骷髅的随机前后侧移，为0b则原地射击。冷却、概率失败、缺少弹药或动作资源冲突时不提交弓箭移动，也不再拦截原版导航或移动控制。生物是否实际追击，仍取决于当时是否存在能够运行的原版Goal或Brain行为。原版RangedBowAttackGoal的屏蔽范围保持不变，防止骷髅绕过PMB射击规则。

原版RangedBowAttackGoal的拉弓、射箭和侧移写入会被屏蔽，以避免骷髅绕过本技能的模式、概率、冷却或mobileWhileShooting；PMB自身的后退与随机游走指令仍可正常通过。拉弓姿势会在模型动画的最后阶段强制覆盖，避免僵尸或灾厄村民等模型自己的攻击、抱手动画再次覆盖双臂；卫道士和唤魔者的专用手持物品层也会显示弓和双臂。

### 盾牌

目前实现了基础的盾牌使用。
符合条件的生物会循环检查是否可以举盾，检查结果受可配置的概率影响。

<details>
<summary>触发、格挡与破盾细节</summary>

举盾触发条件:

1. 实体属于生物，并且preferredHand目标手已有原版盾牌，或可从FetchSource永久换入。
2. 启用(enable)为真。
3. 存在一个进入举盾范围(range)，存活且在视线内的敌对目标。
4. 不处于举盾冷却时间(cooldownTicks)。
5. 不处于破盾攻击造成的强制禁用时间(axeDisableCooldownTicks)。
6. 概率举盾检查(shieldChance)成功。
7. 生物没有启用NoAI。

由本模组控制的盾牌从举盾首个游戏刻起即可格挡，不使用原版玩家盾牌的初始生效延迟。

由本模组控制的盾牌会在可用时优先根据攻击者实体位置计算格挡角度，而不是只依赖原始伤害来源位置。这可以避免贴脸攻击或交互距离延长时，伤害来源位置越过防御者导致角度翻面，并表现为穿盾。

如果服务端仍认为生物正在使用盾牌，即使内部举盾计数刚刚归零，本模组也会在最终过渡游戏刻继续识别实际使用手。ActionBinding校验实际使用手的物品，并接受盾牌耐久变化或破碎的授权更新。动作结束释放绑定，保留最终装备布局。

举盾后，盾牌会在成功格挡攻击时正常损失耐久。

能够禁用盾牌的攻击每次会消耗一点盾牌韧性；当前一轮受到的此类攻击次数达到配置值时，本次举盾才会中止并触发强制禁用时间。

计数会在普通冷却自然结束时刷新，在强制禁用结束、开始新一轮前刷新，并会在本次举盾未真正破盾但被中断时立即刷新。

盾牌反作用力、耐久损耗和盾牌韧性消耗在每个普通伤害间隔内最多触发一次。被实体伤害冷却忽略的额外攻击不会积累这些效果。

被盾牌完全格挡的攻击不会产生原版暴击粒子，但本模组会在玩家攻击蓄力重置前记录其是否满足原版暴击条件。

可破盾暴击会消耗critToughnessDamage点盾牌韧性；若盾牌尚未被破坏，可破盾暴击会播放僵尸敲击木门的音效并产生10个橡木门碎屑粒子，普通可破盾攻击产生6个粒子，其他任何被格挡的攻击产生3个粒子。
真正破盾时则播放僵尸摧毁木门的音效，产生24个粒子，并施加由disableKBMultiplier控制的额外破盾击退。

真正破盾后，生物会进入disableVulnerTicks游戏刻的破盾虚弱。

破盾虚弱期间，生物无法攻击，会持续清空目标和导航，并压制AI移动输入，但保留击退或其他外力造成的已有速度，同时显示类似僵尸村民被治愈或猪灵僵尸化时的抖动效果。

此机制不会启用NoAI，因此重力等正常物理效果仍然生效。此期间受到的伤害会乘以vulnerDamageMultiplier。若disableVulnerTicks为0，则跳过破盾虚弱。

为了避免与Guard Villagers模组冲突，命名空间为guardvillagers的实体不会使用本模组的盾牌行为。

</details>
